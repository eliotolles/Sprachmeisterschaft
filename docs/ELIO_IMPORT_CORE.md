# Structured import and document extraction

Authenticated POST `/api/core/import/collection` routes grammar through the tested grammar importer. Vocabulary, exam, listening, writing and speaking collections are validated and inserted into `ee_records` only. Required source IDs and levels are retained. Vocabulary also maps source items to legacy `words`. Personal imports remain private; only stored Admin roles may create shared imports. Existing source collections are rejected, not replaced. A deterministic owner/kind/source-ID record key and conflict-safe INSERT prevent concurrent duplicate creates. No shared vocabulary bulk migration or schema write is performed by this route.

POST `/api/core/import/extract` accepts up to 20 image/PDF attachments within the AI adapter's 14-million base64-character limit. A configured vision provider returns structured pages, exact text and table rows, suggested module and warnings. Output validation, bounded requests, signed continuations and provider fallback apply. The draft is explicitly requiresReview/saved=false, includes a source digest, and never automatically becomes a trusted answer key. No raw scan is written to the database. Absence of a vision provider fails closed. Very large books require caller page batches; native page splitting, DOCX parsing and playlist ingestion are not implemented by this backend.

Listening dictation can select itemId inside an imported collection as well as existing flat listening records. Source UI, layout and controls remain unchanged. UI binding and real scanned-document extraction require further verification; offline tests do not establish OCR accuracy.
